# GitHub repository and v1.0.0 release guide

This project already has an existing repository: `evilslon/JetSport-FT10C-Sync`. The release workflow is an update to that repository, not the creation of a new repository.

## Repository

- Repository: https://github.com/evilslon/JetSport-FT10C-Sync
- Keep the existing `.git` directory, branches, tags and commit history.
- Do not reinitialize Git, force-push, delete historical tags, or replace the repository with a fresh import.
- Keep the default branch and remote configuration already used by the checkout unless the owner intentionally changes them.

## Release candidate

- Tag to create after final review: `v1.0.0`.
- Release title: `JetSport FT-10C Sync v1.0.0`.
- Release notes: `RELEASE_NOTES_1.0.0.md`.
- Source baseline: user-tested `0.6.0.26`, including the subsequent test synchronization/documentation correction.
- User validation: debug build succeeded, 128 JVM unit tests passed, and the installed APK was confirmed working on Huawei Nova 10 SE / Android 13 with FT-10C.

## Before publishing

1. Confirm the copyright-holder wording in `LICENSE` and review third-party dependency/source attribution.
2. Review the full diff in the existing local checkout.
3. Confirm no `local.properties`, signing keys, personal BLE logs, IDE caches, build outputs or private data are staged.
4. Confirm the source archive contains no `.git` directory and has a valid ZIP structure.
5. Decide whether to publish source only or attach a separately verified APK. The supplied source archive does not include an APK.

## Commit and tag

Follow `docs/UPDATE_EXISTING_REPOSITORY_WINDOWS.md`. Do not commit or push until the owner has reviewed the staged diff and explicitly decided to publish. Preserve the existing history and `v0.5.3.27` tag.

## GitHub Release assets

Recommended assets:
- Source snapshot generated by GitHub from tag `v1.0.0`.
- Optional APK only if the exact APK is built from the tagged source, installed and smoke-tested, and the owner chooses to distribute it.

Use `RELEASE_NOTES_1.0.0.md` as the release description. State clearly whether an APK is attached; do not describe a debug APK as a signed production build.
